# CLAUDE.md

HookRelay is a developer-first webhook delivery platform. A Go API ingests events into
PostgreSQL, a Go worker delivers them to registered endpoints with signed HTTP requests,
exponential-backoff retries and a full attempt history, and a Next.js dashboard shows
what happened.

**Status:** Phases 0–2 are complete: scaffolding; schema and data access; and the API (API-key auth, endpoint CRUD, event ingestion). Integration tests pass on a Neon test branch. Next is Phase 3 (delivery core). Follow `docs/IMPLEMENTATION_PLAN.md` phase by phase.

## Docs (read before making design changes)
- `docs/PRODUCT_SPEC.md`: what we're building and what is out of scope for the MVP.
- `docs/ARCHITECTURE.md`: decisions D1–D8, data flow, schema, API, pitfalls.
- `docs/IMPLEMENTATION_PLAN.md`: phased MVP plan with checklists.
- `docs/API.md`: REST API reference for implemented routes. Update it whenever a route changes.

If an implementation needs to deviate from the architecture, update `ARCHITECTURE.md` in
the same change and explain why.

## Stack
Go (Chi, pgx/v5, sqlc, goose, Asynq, slog) · PostgreSQL 18 (Neon in prod, `postgres:18`
locally) · Redis · Next.js + TypeScript + Tailwind + shadcn/ui · Docker · k6 · GitHub Actions.
Do not add new infrastructure dependencies (no ORMs, brokers or frameworks) without discussing it first.

## Non-negotiable invariants
1. **Postgres is the source of truth.** Redis/Asynq is only a dispatch channel. Losing Redis must never lose an event or a delivery.
2. **Ingest never touches Redis.** Writing the event and fanning out deliveries happen in one DB transaction (transactional outbox). Only the dispatcher enqueues.
3. **Postgres owns retry state.** Asynq tasks use `MaxRetry(0)`. Retries are expressed as `status='scheduled'` + `next_attempt_at`.
4. **Every state transition is a conditional UPDATE** (`WHERE status = <expected>`, plus an `attempt_count` fence when recording results). Never use an unconditional status write.
5. **Never make an outbound HTTP call inside a DB transaction.** The sequence is claim tx, then send, then record tx.
6. **Sign and send the exact stored payload bytes.** Never re-marshal the payload.
7. **Use DB time (`now()`) for scheduling comparisons**, not the Go clock.
8. Lease (`locked_until`) > Asynq task timeout > HTTP timeout. This is validated in config at startup.
9. All outbound delivery goes through the SSRF-guarded client. Never use `http.DefaultClient` for webhooks.
10. Every query is scoped by `project_id`.

## Commands
Run from the repo root. On Windows, use Git Bash (Makefile recipes are POSIX sh).
The Makefile loads `.env` and exports it to recipes.
```
make env               # create .env from .env.example with a random HOOKRELAY_ENCRYPTION_KEY
make dev-up            # docker compose up -d --wait (Postgres + Redis, waits for healthy)
neon deploy            # apply neon.ts to the linked Neon branch and pull DATABASE_URL(_UNPOOLED) into .env
make dev-down          # stop services (dev-reset also deletes the Postgres volume)
make migrate           # hookrelay migrate up   (also: migrate-down, migrate-status)
make create-project NAME="Acme"   # project + first API key; prints the key ONCE
make run-api           # go run ./cmd/hookrelay api  -> http://localhost:8080/healthz, /readyz
make sqlc              # regenerate internal/store/sqlcgen after editing db/queries or migrations
make sqlc-check        # sqlc diff + sqlc vet (fails if generated code is stale)
make test              # go test ./...  (DB/Redis integration tests run if TEST_DATABASE_URL/TEST_REDIS_URL are set, else skip)
make fmt / fmt-check / vet / lint
make tools             # install pinned golangci-lint v2.15.0 + sqlc v1.31.1
make ci                # fmt-check + vet + lint + sqlc-check + test, same as CI
make build             # bin/hookrelay
```
CLI directly: `hookrelay migrate up|down|status|version`, `hookrelay admin create-project --name N [--key-name K]`,
`hookrelay admin create-key --project ID [--name K]`. `admin` and `migrate` log to stderr and print results to stdout.

sqlc needs cgo to `go install`. On Windows without a C compiler, download the release binary
(`sqlc_1.31.1_windows_<arch>.zip` from github.com/sqlc-dev/sqlc/releases) into `~/go/bin`.

## Configuration
All config comes from env vars, parsed in `internal/config` (see `.env.example`). Loading is
strict: any unknown `HOOKRELAY_*` var, malformed value, or broken lease invariant is a
startup error, and all problems are reported together. When adding a variable, add it to
`knownVars`, to `.env.example`, and to the tests. Never log or return connection strings.
`HOOKRELAY_ENCRYPTION_KEY` (base64, 32 bytes) is required. Losing it makes stored endpoint secrets unreadable.

## Conventions
- Go: pass `context.Context` everywhere. Wrap errors with `fmt.Errorf("...: %w", err)`. Log with `slog` and include `delivery_id`/`event_id`/`request_id` fields. Do not use global state beyond `main`.
- SQL is hand-written in `db/queries`, then sqlc generates the code. Never edit generated files.
- Schema changes go in a new goose migration with a working `-- +goose Down`. Never edit an applied migration. Run `make sqlc` afterwards; `docs/ARCHITECTURE.md §4` summarizes the schema and must be kept in sync.
- Tenant-owned tables carry `project_id`, and child rows use composite FKs `(project_id, id)`. Every query on tenant data takes `project_id`. The only exception is `GetActiveAPIKeyByHash`, which is how the project is determined.
- Multi-statement writes go through `store.InTx`. Never make network calls other than to Postgres inside it.
- Secrets: never log plaintext API keys, signing secrets or the encryption key. `secrets.Key` and `secrets.APIKey` redact themselves in fmt/slog; keep it that way for any new secret type. Use `store.IsUniqueViolation`/`IsForeignKeyViolation`/`IsNotFound` instead of matching error strings.
- HTTP errors use the envelope `{"error":{"code","message"}}` (see `writeError` in `internal/httpapi`).
- Integration tests read `TEST_DATABASE_URL` / `TEST_REDIS_URL` and must `t.Skip` when they are unset. Locally they run against a Neon **test branch** (`integration-tests`, its direct URL in `.env` as `TEST_DATABASE_URL`), never `production`. CLI tests must set both `DATABASE_URL` and `DATABASE_URL_UNPOOLED`, or `migrate` would follow the developer's real URL. For Postgres, use `pgtest.NewMigrated(t)` / `pgtest.NewEmpty(t)` (fresh database per test, dropped on cleanup).
- Tests for anything that touches state transitions are integration tests against real Postgres and Redis, not mocks.
- The dashboard must never expose the API key to the browser. Use Server Components or Route Handlers only.
- Keep the MVP small. Check `PRODUCT_SPEC.md §6` before adding features.
